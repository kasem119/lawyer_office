# دمج المستشار في محامي

هذه النسخة تدمج مجموعة القوانين مع المساعد الحالي، دون نقل تطبيق Flutter أو Firebase أو حساباته. خدمة Python خاصة تسترجع النصوص عبر SQLite FTS5؛ خادم Express يتحقق من الحساب والمكتب والقضية ثم يرسل المقاطع إلى Gemini باستدعاء واحد. البحث نصي وليس نسخة البحث الدلالي Chroma. سجلات النشر والتحقق المحفوظة في `artifacts/MUSTASHAR-DEPLOYMENT-RESULT.json` و`artifacts/MUSTASHAR-PRODUCTION-SMOKE.json` توثق نشرًا سابقًا وطلبًا إنتاجيًا ناجحًا؛ لا تمثل فحصًا مباشرًا لحالة الإنتاج الحالية.

## التشغيل

1. بيانات التشغيل موجودة محليًا في `services/legal-retrieval/data/`، ومستثناة من Git. تتضمن النص المستخرج وملفات PDF؛ لا تنقل ملفات `.env` أو `.git` أو cache من المشروع الأصلي.
2. ابن الفهرس صراحة: `python services/legal-retrieval/retrieval.py build --data-dir services/legal-retrieval/data`.
3. أنشئ رمزًا عشوائيًا مستقلًا من 32 حرفًا على الأقل. اضبط `LEGAL_RETRIEVAL_TOKEN` بنفس القيمة في بيئة خدمة Python و`server/.env`، ولا تضعه في الواجهة أو Git.
4. شغّل Python مع `LEGAL_RETRIEVAL_DATA_DIR` كمسار مطلق لمجلد البيانات: `python services/legal-retrieval/server.py`. العنوان الافتراضي `127.0.0.1:8100`؛ لا تنشر المنفذ أو تضف proxy عامًا له.
5. اضبط `AI_PROVIDER=mustashar` و`LEGAL_RETRIEVAL_URL=http://127.0.0.1:8100` و`GEMINI_API_KEY` بمفتاح جديد و`GEMINI_MODEL=gemini-3.5-flash-lite` في `server/.env`، ثم أعد تشغيل خادم محامي. المفتاح القديم متتبّع في مستودع المصدر ويحتاج تدويرًا.
6. سجّل الدخول بحساب مكتب وافتح المساعد: الحالة تعرض جاهزية الاسترجاع وإعداد المفتاح؛ طلب حقيقي ناجح وحده يثبت استجابة المزود.

## السلوك والحدود

- الطلب حتى 4,000 حرف، مع 4 مقاطع كحد أقصى و4,800 حرف للسياق القانوني، واستدعاء نموذج واحد وإجابة حتى 1,200 توكن. مستوى التفكير مضبوط على الحد الأدنى لنموذج Flash-Lite الافتراضي. تجاوز الطلب يُرفض دون بتر صامت.
- عند غياب سند كافٍ لا يُستدعى النموذج. أخطاء المزود لا تتحول إلى قوالب محلية تبدو كإجابة مسندة.
- المراجع أصلها الفهرس، مع القانون والصفحة ومقتطف النص؛ PDF يُحمّل عبر مسار محمي باستخدام معرّف ثابت. أرقام المراجع والمواد غير المدعومة تُرفض، ويُشترط أن يرد رقم المادة في مقتطف استندت إليه الإجابة فعلًا. هذا تحقق بنيوي للمراجع وليس إثباتًا آليًا لصحة الاستدلال القانوني.
- لا توجد ذاكرة إجابات مشتركة ولا سجل أسئلة. ملخص القضية يرسل العنوان والنوع والحالة فقط؛ لا يرسل أسماء الأطراف أو الهواتف أو أرقام القضايا. النص الذي يكتبه المستخدم قد يتضمن بيانات شخصية؛ الواجهة توضّح إرسال الطلب للمزود.
- حد 10 طلبات لكل مستخدم/مكتب في الدقيقة، و4 طلبات متزامنة لكل عملية Express. المهلة والإغلاق يلغيان الاتصال بالمزود.
- المصدر مجموعة من 45 ملفًا، وليس ضمانًا لاكتمال التشريعات أو نفاذها الحالي. النص المستخرج يشمل أخطاء OCR ونقصًا في بعض القوانين؛ التعديلات لا تُدمج آليًا. راجع الأصل قبل الاعتماد.

## التحقق والنشر

`python -m unittest discover -s services/legal-retrieval/tests`، ثم `node server/tests/legal-assistant.mjs`، واختبارات الصلاحيات وبناء الواجهة. الاختبارات تستخدم قاعدة بيانات مؤقتة ومزودًا وهميًا دون استهلاك مدفوع.

النشر يحتاج خدمة systemd منفصلة باسم `muhami-legal-retrieval` بحساب غير root وبيئة محمية، بيانات قوانين للقراءة فقط وفهرس مبني مسبقًا، ونسخة احتياطية للخادم والواجهة. اختبر رمز الخدمة، جاهزية الفهرس، طلبًا مسجلًا ومراجع PDF، و401 للمجهول و403 للبوابة ومالك المنصة. لا تنشر مفتاح المصدر القديم أو بيانات المكتب المحلية. بيانات القانون العامة مستقلة عن SQLite الخاص بالمكاتب.
